# The Accused (Interrogation)

# برومبت لـ  — لعبة "الاستجواب"



أريد منك بناء موقع ويب للعبة استجواب نصية تفاعلية اسمها **"الاستجواب"**. اقرأ كل التفاصيل التالية بعناية قبل البدء.



---



## 1) الفكرة العامة



اللاعب يدخل في دور شخصية محددة مسبقًا (متهم بريء، فاعل حقيقي، شاهد خائف، شريك متردد... حسب القضية) ويخضع لاستجواب من محقق أو أكثر. اللعبة تتتبع كل إجابة يعطيها اللاعب، وتكتشف التناقضات تلقائيًا بين إجاباته المختلفة، وتواجهه بها المحقق حيًا أثناء الحوار. النتيجة النهائية (من ضمن نهايات متعددة) تعتمد على أداء اللاعب داخل دوره، وليس فقط على "صح أو خطأ".



### بنية كل قضية

- **دور ثابت محدد مسبقًا** لكل قضية (القضية نفسها تقرر هل اللاعب بريء تحت شبهة، فاعل حقيقي، شاهد، أو شريك — هذا ليس اختيار اللاعب ولا عشوائي، بل جزء من تصميم القضية).

- **بطاقة تعريف** تُعرض في بداية كل قضية قبل بدء الاستجواب (انظر القسم 3).

- **محقق أو محققان** يجريان الاستجواب، بمستويات صعوبة مختلفة (انظر القسم 4).

- **نهايات متعددة** تعتمد على مستوى الشك المتراكم + التناقضات + هل حافظ اللاعب على سره الشخصي إن وُجد.



---



## 2) الشروط التقنية (إلزامية)



- **بدون أي قاعدة بيانات وبدون سيرفر باك-إند.** الموقع بالكامل Static: HTML + CSS + JavaScript فقط.

- كل محتوى القضايا (بطاقات الأدوار، الأسئلة، قواعد التناقض، النهايات، بيانات الشخصيات) يُخزَّن في **ملفات JSON** منفصلة لكل قضية، يتم تحميلها من جهة العميل.

- تقدم اللاعب وسجل القضايا التي أنهاها يُحفظ في **localStorage** فقط، بدون أي حساب أو تسجيل دخول.

- المشروع قابل للاستضافة مجانًا بالكامل (GitHub Pages / Vercel / Netlify).



---



## 3) بطاقة الشخصية / الدور (شاشة ما قبل الاستجواب)



قبل كل قضية، تُعرض شاشة تمهيدية كاملة (Full Screen Card) تحتوي:

- اسم القضية ورقمها

- دور اللاعب (مثال: "أنت بريء تحت شبهة")

- الحقائق التي يعرفها اللاعب فقط (ولا يعرفها المحقق)

- هدف اللاعب من هذا الاستجواب

- زر "ابدأ الاستجواب"



هيكل JSON لهذا الجزء:

```json

{

  "case_id": "case_01",

  "case_title": "قضية اختفاء المبلغ من الخزنة",

  "fixed_role": "innocent_suspicious",

  "role_card": {

    "role_name": "أنت بريء، لكن كل الظروف تدينك",

    "secret_truth": "كنت في المكتب الساعة 9 مساءً لمقابلة شخص سري لا علاقة له بالسرقة",

    "objective": "أثبت براءتك دون كشف سرك الشخصي",

    "known_facts": [

      "كنت هناك فعلاً بين الساعة 8:45 و9:20",

      "رأيت ظلّ شخص آخر يدخل من الباب الخلفي",

      "بصمتك موجودة على الخزنة من قبل الحادثة بأسبوع"

    ]

  }

}

```

## 4) شخصيات المحققين (مهم جدًا)



أريد **عدة شخصيات محققين مختلفة**، كل واحدة برسمة توضيحية (Illustration) مميزة وأسلوب استجواب ومستوى صعوبة مختلف. هذه الشخصيات تُستخدم عبر قضايا مختلفة (يمكن تكرار نفس المحقق في أكثر من قضية).



### أمثلة الشخصيات المطلوبة (صمم على الأقل 3، ويفضّل أكثر):



**المحقق أحمد — مستوى سهل**

- شخصية متساهلة، يصدق بسهولة، لا يلاحظ التناقضات الصغيرة، يعطي فرصًا لتصحيح الإجابة

- تأثير في المنطق: `contradiction_sensitivity: low`, `suspicion_increase_rate: 0.5x`



**المحققة سارة — مستوى متوسط**

- منطقية ومتوازنة، تلاحظ التناقضات الواضحة فقط، تعطي مؤشرات غير مباشرة أنها شاكة



**المحقق عمر — مستوى صعب**

- حاد الملاحظة، يحفظ كل كلمة قالها اللاعب، يواجه بأدق التفاصيل، يستخدم أسلوب ضغط نفسي (يكرر السؤال بصياغة مختلفة ليكشف الكذب)

- `contradiction_sensitivity: high`, `suspicion_increase_rate: 1.5x`



**قضايا خاصة: محققان في نفس الوقت**

في بعض القضايا (المتقدمة) يجلس محققان معًا يستجوبان اللاعب بالتبادل — واحد "الشرطي الجيد" (يتعاطف، يخفف الضغط) والآخر "الشرطي السيئ" (يضغط ويهدد). هذا يضيف تعقيدًا: أحيانًا يتناقض المحققان نفسهما في أسلوبهما، ويجب أن يعكس تصميم الحوار هذا التبادل بصريًا (تبديل من يتكلم مع صورته/اسمه فوق فقاعة الحوار).



هيكل JSON للمحقق:

```json

{

  "detective_id": "ahmed",

  "name": "المحقق أحمد",

  "difficulty": "easy",

  "avatar": "ahmed.svg",

  "personality_tone": "متساهل وودود",

  "contradiction_sensitivity": 0.5,

  "suspicion_multiplier": 0.7,

  "signature_lines": {

    "greeting": "تفضل اجلس، بس كم سؤال بسيط وخلصنا.",

    "on_contradiction": "أممم، بس انت قلت شيء مختلف قبل شوي... ممكن توضح؟",

    "on_confession": "خلاص، صدقتك من الأول بصراحة."

  }

}

```



### الشكل البصري للمحققين

- شخصيات **مرسومة (Illustrated)** بأسلوب فلات ديزاين ناعم (Flat / Semi-flat design)، ليست صور فوتوغرافية واقعية.

- كل شخصية لها تعبيرات وجه متعددة (عادي، شاك، غاضب، مقتنع) تتغير حسب حالة الاستجواب — يمكن تنفيذها كـ SVG بسيط بعدة حالات يتم التبديل بينها بـ CSS/JS، أو كصور PNG/SVG معدة مسبقًا بعدة تعابير.

- تصميم الشخصية يعكس شخصيتها (مثال: أحمد يرتدي نظارة وابتسامة مرحة، عمر ملامحه حادة وجاد ولباسه رسمي صارم).

## 5) التصميم البصري (Light Mode) — مهم جدًا



- **لايت مود بالكامل**، ألوان فاتحة، مبهجة لكن أنيقة (ليست صارخة)، تناسب أجواء "غرفة تحقيق" حديثة نظيفة وليست كئيبة أو مظلمة.

- لوحة ألوان مقترحة: خلفيات بيضاء/كريمية دافئة، لمسات لون رئيسي واحد مميز (مثال: أزرق نيلي أو كستنائي دافئ) للأزرار والعناصر التفاعلية، ولون تنبيه (أحمر/برتقالي ناعم) لمؤشر الشك عند الارتفاع.

- خطوط عربية واضحة وأنيقة (مثال: Cairo, Tajawal, أو ما يناسبها من خطوط Google Fonts العربية) بحجم مريح للقراءة الطويلة.

- تصميم البطاقات والحوار بزوايا دائرية ناعمة، ظلال خفيفة (Soft Shadows)، مسافات بيضاء مريحة (لا يكون الشكل مزدحمًا).



### مؤثرات وتفاعلات مطلوبة عند الضغط والأحداث

- **عند اختيار إجابة:** تأثير بصري فوري (مثل نبضة خفيفة/Scale animation على الزر المختار، وتلاشي بقية الخيارات).

- **عند ظهور تناقض:** اهتزاز خفيف (Shake animation) لفقاعة حوار المحقق + تغيّر تعبير وجه الشخصية إلى "شك" + صوت أو خط أحمر يظهر لحظيًا حول مؤشر الشك مع ارتفاعه.

- **مؤشر الشك (Suspicion Meter):** شريط تقدم دائم الظهور أعلى الشاشة، يتحرك بحركة سلسة (Smooth transition) عند كل تغيير، ويغيّر لونه تدريجيًا من أخضر (آمن) إلى أصفر (حذر) إلى أحمر (خطر).

- **عند ظهور رسالة المحقق الجديدة:** تأثير كتابة تدريجي (Typewriter effect) أو ظهور تدريجي (Fade + slight slide up) لمحاكاة إحساس الحوار الحي بدل ظهور النص دفعة واحدة.

- **عند فتح بطاقة الدور في البداية:** تأثير انقلاب بطاقة (Card flip) أو انزلاق أنيق (Slide + fade) كأنك تفتح ملفًا سريًا فعليًا.

- **عند الوصول لنهاية القضية:** شاشة ختامية بتصميم مختلف (مثال: طابع "مغلق/QUALIFIED CLOSED" يظهر بحركةختم Stamp animation) مع عرض ملخص الأداء (عدد التناقضات، أعلى نسبة شك وصلها، هل حافظ على سره).

## 6) التجاوب مع الهاتف والكمبيوتر (Responsive)



- على الكمبيوتر: تخطيط أفقي يظهر فيه صورة/رسمة المحقق (أو المحققَين) بشكل بارز على جانب، وفقاعات الحوار وخيارات الإجابة على الجانب الآخر أو أسفل الشاشة، مع مؤشر الشك ثابت أعلى الصفحة.

- على الهاتف: تخطيط عمودي، صورة المحقق أصغر وثابتة أعلى الشاشة، فقاعات الحوار تتوسط الشاشة، أزرار الخيارات كبيرة بحجم مناسب للمس (لا تقل عن 44px ارتفاعًا)، مؤشر الشك شريط رفيع أعلى الشاشة دائم الظهور.

- كل الحركات والمؤثرات (transitions/animations) يجب أن تعمل بسلاسة على الهاتف دون تهنيج (استخدم CSS transforms/opacity بدل خصائص تسبب إعادة رسم ثقيلة).



---



## 7) آلية التتبع والتناقض (المنطق التقني)



- كل إجابة يختارها اللاعب تُخزَّن مع "tags" (مكان، وقت، أشخاص، أفعال).

- عند كل إجابة جديدة، يفحص الكود إذا فيه تعارض بين tags الحالية والسابقة وفق `contradiction_rules` المعرّفة في JSON الخاص بالقضية.

- عند اكتشاف تعارض: يرتفع مؤشر الشك بمقدار محدد (متأثر بـ `suspicion_multiplier` الخاص بالمحقق)، ويُعرض سطر مواجهة (confrontation_line) مخصص لهذا التعارض.

- الأداء التراكمي (شك نهائي + تناقضات + سر انكشف أم لا) يحدد أي "نهاية" من `endings` تُعرض.



هيكل JSON مختصر للتناقض والنهايات:

```json

{

  "contradiction_rules": [

    {

      "tag_conflict": ["location:home", "witness_saw:outside"],

      "confrontation_line": "الجارة تقول شافتك بالخارج، فسّر لي هذا",

      "suspicion_change": 25

    }

  ],

  "endings": [

    {

      "condition": {"suspicion_max": 30, "secret_revealed": false},

      "ending_id": "clean_innocent",

      "text": "المحقق يعتذر لك، خرجت بريئًا وسرّك بقي آمنًا معك."

    }

  ]

}

```

## 8) المطلوب مني الآن (خطوات التنفيذ)



1. ابنِ الهيكل التقني الكامل أولاً: شاشة بطاقة الدور، شاشة الحوار مع مؤشر الشك، منطق تتبع التناقضات، شاشة النهاية.

2. صمم واقعيًا (بأسلوب مرسوم/Flat design) ثلاث شخصيات محققين على الأقل (أحمد سهل، سارة متوسطة، عمر صعب) بتعبيرات وجه متعددة لكل منهم.

3. اكتب أول قضية كاملة وشغالة (دور محدد + بطاقة + 20-25 سؤال + 5 قواعد تناقض + 5 نهايات مختلفة) باستخدام المحقق أحمد (سهل) كبداية تجريبية.

4. اربط كل شيء وتأكد أن التجربة سلسة وجميلة على الهاتف والكمبيوتر مع كل المؤثرات المذكورة في القسم 5.

5. بعد التأكد من نجاح القضية الأولى، جهّز البنية بحيث يسهل إضافة قضايا ومحققين جدد لاحقًا بمجرد إضافة ملفات JSON جديدة دون تعديل الكود الأساسي.



## 9) اللغة

كل المحتوى (الواجهة، الحوار، النصوص) باللغة العربية الفصحى المبسطة أو العامية الواضحة (اختر ما يناسب الحوار الطبيعي بين محقق ومتهم، على أن يبقى مفهومًا لكل الناطقين بالعربية).
